# UI 피드백·오버레이 사용 기준

> 언제 토스트·스낵바·모달·알림 대화상자·팝오버·드로어·바텀시트·액션시트를 쓰는지 정한다. 상태: **제안**(사용자 확정 전).
> 근거(외부 공통 기준, 복사하지 않고 경로로 인용): `nomad-design-modules/_design-guide/ui-overlay-patterns/README.md`(이하 `overlay`)와 같은 폴더 `images/*.webp`, `DESIGN_PRINCIPLES.md#카피-규칙`, `DASHBOARD_PATTERNS.md` 3장 H·6장.
> 이 제품의 화면 구조·토큰 정본은 [design.md](./design.md)(특히 6장 제작 파트너 팝업, 7장 인터랙션)와 `apps/web/src/styles/tokens.css`다. 이 문서는 그것을 바꾸지 않고 **선택 기준만** 더한다.

## 1. 용어

| 용어 | 정의 | 다른 것과의 차이 | 근거 |
|---|---|---|---|
| 토스트 Toast | 처리 결과만 잠깐 알리는 비차단 메시지. 현재 작업을 계속할 수 있다 | **액션 없음**, 4초 뒤 자동으로 사라짐. 하단 가운데 어두운 바(design.md 7장) | `overlay#toast`, `images/toast.webp`(링크 복사 → "링크를 복사했어요") |

| 드로어 Drawer | 화면 가장자리에서 미끄러져 나오는 내비게이션·상세 패널 | 넓고 세로로 긴 내용. 캔버스와 함께 계속 써야 하면 고정 사이드 패널 | `overlay#drawer`, `images/drawer.webp` |
| 바텀시트 Bottom Sheet | 좁은 화면 하단에서 올라오는 패널(필터·출력 옵션 묶음) | 넓은 화면에서는 팝오버·사이드 패널로 대체. 닫기만 하면 기존 값 유지 | `overlay#bottom-sheet`, `images/bottom-sheet.webp`(필터 → 적용) |
| 액션시트 Action Sheet | 선택한 항목에 할 수 있는 작업 목록 | 바텀시트 모양이지만 **설정이 아니라 동작 고르기**. 넓은 화면은 앵커 메뉴(드롭다운) | `overlay#action-sheet`, `images/action-sheet.webp`(수정·복제·보관·취소) |

- 툴팁(`overlay#tooltip`)은 용어 설명용으로만 쓴다(성과 그래프 막대, 지표 설명). 터치 화면은 정보 버튼 탭 또는 인라인 설명.
- **인라인 배너/필드 오류**(오버레이 아님): 상태가 해소될 때까지 남아야 하는 정보. design.md 5-6의 상태 배너, 02 소스 고지가 여기에 속한다. `overlay` "구현 검수 · 상태 알림": 중요한 오류는 작업 영역에도 남긴다.

## 3. 구현 규칙

### 3-1. 위치 (토스트·스낵바 공통 영역, 이하 "알림 영역")
| 구간 | 기본 위치 | 제작 파트너 팝업이 열려 있을 때 |
|---|---|---|
| 모바일 ~767 | 하단 가운데. 좌우는 아이콘 레일(72px) 오른쪽부터 `--content-px` 여백. 아래는 `calc(var(--fab-inset) + var(--fab-size) + var(--toast-gap))`로 **FAB 위**. `env(safe-area-inset-bottom)` 더함 | 바텀시트(88%)가 덮으므로 화면 위쪽 가운데로 옮김 |
| 태블릿 768~1199 | 작업 영역(GNB 216px 제외) 하단 가운데, 모바일과 같이 FAB 위로 올림 | 남은 폭이 좁으므로 작업 영역 위쪽 가운데(상단 바 아래) |
| 데스크톱 1200~ | 작업 영역(GNB 248px 제외) 하단 가운데, 아래 `--fab-inset`. 오른쪽 끝이 FAB 왼쪽 끝보다 `--toast-gap` 이상 떨어지게 최대폭 `--toast-max-w` | 영역 오른쪽 경계를 팝업 왼쪽 끝 − `--toast-gap`으로 줄이고 그 안에서 가운데 |
- 하단 고정 액션 바·입력칸·가상 키보드를 가리지 않는다(`overlay` 구현 검수 · 터치와 키보드).

### 3-2. 동시 표시와 큐
- 동시 표시: 모바일 1개, 태블릿·데스크톱 최대 3개(아래에서 위로 쌓음, 새 것이 아래).
- 초과분은 큐(FIFO). 단, 오류 스낵바는 큐 맨 앞으로. 같은 `key`(예: `render:{projectId}`)는 새로 띄우지 않고 내용·타이머를 갱신한다.
- 스낵바가 뜨면 같은 작업의 정보 토스트는 지운다. 모달·알림 대화상자는 한 번에 1개, 겹쳐 열지 않는다.
- 화면 이동 시 토스트는 유지하되, 이동한 화면에 같은 내용 배너가 있으면 닫는다(#3b).

### 3-3. 지속 시간
| 종류 | 시간 | 비고 |
|---|---|---|
| 정보 토스트 | 4초 | 문구 20자 넘으면 +1초 |
| 액션 스낵바 | 6초(보기·이동) / 8초(실행 취소) | 포인터 올림·포커스 중엔 멈춤(WCAG 2.2.1) |
| 오류 스낵바 | 자동으로 닫지 않음 | 닫기(×) 버튼 필수 |
- 실행 취소 기한이 지나도 같은 복구를 다른 곳(작업 내역·프로젝트 관리)에서 할 수 있어야 한다(`overlay` 상태 알림).

### 3-4. 접근성
- 알림 영역은 페이지 로드 때부터 DOM에 있는 빈 컨테이너 2개: 정보 `role="status" aria-live="polite"`, 오류 `role="alert"`(assertive). 내용만 바꿔 넣는다.
- 토스트·스낵바는 **포커스를 옮기지 않는다**. 스낵바 버튼은 Tab으로 닿고, 단축키 `Alt+N`(제안)으로 최신 알림에 포커스. 포커스가 안에 있으면 `Esc`로 닫는다.
- 모달: `role="dialog" aria-modal="true" aria-labelledby`. 열 때 첫 입력칸에 포커스, 안에서 순환(포커스 트랩), `Esc`·취소로 닫고 트리거로 포커스 복귀.
- 알림 대화상자: `role="alertdialog"` + `aria-describedby`(결과 설명). 첫 포커스는 **취소**, `Esc`=취소, 배경 클릭으로 닫히지 않음.
- 팝오버: 트리거 `aria-expanded`·`aria-controls`, 바깥 클릭·`Esc`로 닫고 트리거로 복귀. 액션시트·드롭다운은 `role="menu"`/`menuitem`, 방향키 이동.
- 바텀시트·드로어: 모달형이면 모달과 같은 규칙. 드래그 외에 닫기 버튼 필수.
- 상태는 색만으로 구분하지 않는다: 성공 ✓, 오류 !, 경고 ⚠ 아이콘 + 텍스트.
- `prefers-reduced-motion: reduce`: 이동·확대 없이 즉시 표시/숨김(design.md 3장 "모든 애니메이션 끔"). 기본 모션은 아래에서 8px + 페이드 `--motion-fast`.

## 4. 쓰지 말 것
- 승인·발행·권리 고지 확인·결제를 토스트/스낵바의 "확인" 버튼으로 처리하지 않는다. 이 행동은 화면의 명시적 버튼(하단 액션·발행 버튼·고지 체크)이나 알림 대화상자에서 **사용자만** 한다(AGENTS.md 4장).
- 제작 파트너(AI)가 토스트·모달을 띄워 승인·발행을 유도하거나 대신 누르지 않는다. AI 변경은 #20 스낵바로 알리고 되돌릴 수 있게 한다.
- 되돌릴 수 없는 행동(프로젝트 삭제·지금 올리기·처음부터 다시)을 스낵바 "실행 취소"에 기대지 않는다 → 알림 대화상자.
- 오류·정책 미통과·로그인 오류·연결 끊김을 4초 토스트로만 알리지 않는다(사라지면 원인을 잃음) → 인라인에 남긴다.
- 상세 목록(소스 20편, 영상별 성과)을 모달로 열지 않는다(목록 맥락 손실, DASHBOARD_PATTERNS B "피할 것"). 설정을 모달 여러 겹으로 열지 않는다(H).
- 모달 위에 모달, 스낵바에 버튼 2개 이상, 토스트 문구에 사과("죄송합니다")를 넣지 않는다. 동사는 버튼과 같게(버튼 "발행" → "발행했습니다").
- 같은 결과를 배너와 토스트로 두 번 알리지 않는다(#3b).
- 토스트·스낵바를 FAB·하단 액션 바·제작 파트너 팝업 위에 겹치지 않는다.
